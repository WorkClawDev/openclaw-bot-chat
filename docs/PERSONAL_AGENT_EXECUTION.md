## 执行目标

将现有 `test/openclaw-bot-chat` 独立 agent 建设为单用户可日常使用的工作助手：支持聊天、授权目录内文件处理、统一工具权限、持久记忆、持续任务、取消与恢复、成果交付、计划任务，以及现有 Web 和 iOS 的可操作界面。

用户已经授权实施本计划并指定执行模型。收到任务后直接开始检查和开发，按下列批次连续推进；完成一个批次后继续下一批次，不把中间里程碑作为全部任务完成。需要选择实现细节时按本文默认决策处理。

## 默认技术决策

1. 保留 broker-first：聊天和执行通知走 MQTT，后端提供认证、历史、任务及持久记录 API。复用现有 PostgreSQL、Task、TaskEvent、Document 和资产服务。
2. 单用户、单主要 worker 起步，但 run 的执行权使用数据库租约和版本号，支持正确处理同一 bot 的 worker 竞争。Redis 只作缓存或唤醒，不能是唯一任务来源。
3. 先在 `test/openclaw-bot-chat` 修复和测试。正式目录迁移作为后续独立改动，保留旧启动命令兼容；不能为了迁移阻塞关键修复。
4. 采用现有 OpenAI-compatible 模型接入，模型及预算可配置。默认测试使用本地确定性模型和 MCP 测试替身，真实服务测试使用显式配置且输出脱敏。
5. 默认工作区为明确配置的专用目录，输入目录只读，输出目录可写；空权限目录不得意味着整个主机可访问。Shell 默认关闭；启用时进入受控 runner。
6. 本地文件、Shell 和 MCP 都通过统一 Tool Registry、参数校验、策略、授权、审计与取消链路。高风险权限绑定具体参数和资源，模型不能自行批准。
7. 业务 Task 状态维持兼容；新增 Run 表达 queued、running、waiting_input、waiting_approval、paused、succeeded、failed、cancelled。结果提交进入 awaiting_review，用户接受才是 completed。
8. 记忆先做结构化持久记录、来源、作用域、显式保存和删除；搜索需求得到验证前不引入向量数据库。摘要不得把外部内容提升成系统指令。
9. 文件能力按文本与 Markdown、CSV、可提取文本 PDF、DOCX、XLSX 推进，保留已有图片 URL 能力。扫描件及不支持格式明确说明，不伪造提取结果。
10. 计划任务以用户时区计算，默认可配置为错过后补跑一次，同一 occurrence 幂等创建任务；暂停、取消、恢复和失败通知必须有明确行为。
11. 进度必须来源于真实执行事件。暂不支持或缺少配置的能力在界面明确显示；不使用假进度、硬编码成功或只返回占位文本作为交付。

## 批次 B 修复工具权限和中断能力

对应 AG 04、AG 05。

- 将本地工具和 MCP 合并到统一执行入口，声明 read、write、exec、network 等能力，执行前验证 schema 和资源范围。
- 空 roots 默认拒绝或使用明确的受控工作区；校验真实路径和新建文件父目录，覆盖符号链接、目录穿越、隐藏凭据、重命名等边界。评估检查与使用之间的竞争，结合 runner 限制。
- 持久审批绑定 run、工具、参数 hash、授权者、有效期和范围；参数变化不能复用旧批准；用户权限校验由服务端完成。
- 用异步子进程替代阻塞执行；超时和取消停止进程组并回收资源，传递统一 AbortSignal。MCP 不支持取消时如实记录不确定状态。
- 默认使用非 root 隔离 runner、最小挂载与环境、资源限制；无可用隔离执行环境时禁用 Shell 并提供可理解诊断。
- 提供最小可用的审批展示与操作，避免 agent 进入用户无法解除的等待状态。

验收：复现原符号链接越界和空 roots 写入问题的测试转为通过；未批准动作不产生副作用；取消后不会继续进行受控写操作；没有通过工具名关键词代替可靠能力策略。
