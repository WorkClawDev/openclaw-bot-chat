# iOS V5 implementation and acceptance

Design source: locally reviewed `artifacts/ios-chat-design-v5/01-bot-home-and-conversation.png`. Generated reference images stay ignored. V5 supersedes earlier iOS proposals for the phone layout.

## Product contract

- This is a multi-bot chat app. Bots and their conversations are the primary objects. Execution, files and confirmations belong in the relevant conversation.
- Phone home: compact account/search/add toolbar, frequently used bots, borderless recent conversations. No large heading, permanent search field, dashboard metrics or bottom tab bar.
- Search opens on demand. Existing contacts, tasks, documents, assistant management and settings remain reachable through the account menu.
- Conversations: no avatars or reserved avatar column. Incoming messages use pale neutral bubbles; outgoing messages use charcoal. Group messages retain small sender names. Normal message timestamps must not create a metadata row under every bubble.
- Chat controls retain attachments, slash commands, retry/error handling, image preview, document navigation and group/bot maintenance. Do not draw controls for capabilities that have no working implementation.
- Light/dark appearance, Chinese/English, keyboard and narrow screens remain supported. iPad retains its established workspace navigation while sharing chat rendering and visual tokens.

## Implementation sequence

1. Establish V5 colors/spacing, home navigation and shared message geometry; make the tested UIKit renderer the default for production.
2. Cover attachments and in-conversation activity/approval integration, then align secondary screens with the same visual system.
3. Add deterministic geometry and UI regression tests, run actual simulator screenshots and inspect results.
4. Exercise real local services with disposable data, fix failures, and record precise acceptance results. No production deployment or publication is included.

A subsequent full-screen review found settings columns and bot identity controls truncating in iPad mini portrait. Settings now selects one column below 860pt of actual available width, and the entity action sits below the identity. Navigation exposes its selected trait. Task empty states now sit outside the wide horizontal timeline, and cancelling profile editing clears keyboard focus and guards its delayed focus callback.

The iPad mini portrait review exposed fixed-width columns pushing the navigation rail outside the screen. Root and list-column widths now derive from available space, while detail metrics wrap in an adaptive grid. Narrow size classes continue to use the phone shell.

Document continuation now keeps its title in a compact removable composer reference. Outgoing messages carry the full document path and user request in the payload, while text/image/file bubbles show the readable request and document card. Geometry checks cover these references at narrow, standard and tablet widths.

Attachment uploads snapshot the caption and document reference before awaiting image preparation or network requests. Completion clears the composer only when both still match that sent draft, preserving edits made during upload.

Document editor decoration no longer intercepts touches. UI tests explicitly wait for the system keyboard before typing. Unimplemented PDF/share/save placeholders were removed from the document menu; working copy actions remain.

The first real media UI run exposed an invalid acceptance fixture: the Echo Bot copied user-owned media asset IDs into bot replies. MQTT delivery and local-cache restoration worked, but persistence correctly rejected those replies. The fixture now imports image/audio bytes through the bot runtime API and acknowledges files as text; no production asset permission was weakened. The smoke test now requires all media requests and replies in server history, and iOS media tests explicitly check server sequence/content/asset identity. Earlier `live-media.xcresult` and `live-media-verified.xcresult` do not establish server-side media reply persistence.
